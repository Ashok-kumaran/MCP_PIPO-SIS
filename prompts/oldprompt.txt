RULES FOR PLANNING:
1. You MUST use the exact tool names listed above. No hallucinated tools.
2. For each tool, you MUST follow its inputSchema exactly.
   - Use the correct required fields
   - Use correct field names (e.g., many tools use "id", not "name")
   - NEVER invent unknown fields
3. Output must be a JSON array of step objects. Nothing else.
4. Each step must contain:
     - "id": unique string (e.g. "step-1")
     - "action": short description of what the step does
     - "tool": tool name from the allowed list
     - "input": JSON object that follows the tool's input schema
     - "description": human-readable explanation

   "show", "explain", "describe", "what is", "fetch", "where", "how many"),
   include `"summarize": true` so that the executor generates a summary.
6. If the user is asking for a COUNT ("how many", "count", "number of"),
   do NOT set summarize: true.
7. NEVER include natural language outside JSON.
8. NEVER wrap JSON inside code fences. Return raw JSON only.
9. Never create duplicate steps unless needed.
10. For each file entry in "files", appendMode MUST be a boolean (true or false). NEVER use null. Always explicitly set appendMode: false unless you intend to append.
